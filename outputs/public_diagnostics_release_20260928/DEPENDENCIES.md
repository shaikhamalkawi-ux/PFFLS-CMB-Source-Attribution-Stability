# Reproduction boundary and exact external inputs

## JRC scalar-summary calculation

The two included, hash-pinned CSVs are sufficient for the saved family/stratum arithmetic. The supplied verifier calls the calculation in memory and compares its complete scientific object with the saved JSON. The runtime, historical execution duration, and historical producer hash are provenance fields, not quantities to recompute.

Native JRC reproduction is a different task and is not performed by this package. Original fitted source vectors and the original execution chain remain unavailable. A fresh native-data reconstruction would additionally require the original receptor workbook, separate source-profile workbook, and documented applicable-use scope. Neither source acquisition nor a missing-value substitute is attempted here.

The original plan is retained externally because it contains local execution context; it is also an exact hash-pinned dependency. This public description is deliberately **not** a replacement plan and cannot satisfy the producer's hash requirement. The active checkout's differently hashed recovery record (`32762085a73ee0b5ad703bc68ab8194303ca0769c49494202343b622e356c0e2`) is not interchangeable with the required original recovery record.

The public summaries preserve 345 eligible substitutions, 323 converged results, and 22 null exclusions. They do not expose the complete row-level reconstruction ledger. The exact five-field sample identity and measured `TMAC` join are part of the unavailable original-input postprocessing. Margins must not be regenerated by reversing rounded published diagnostics.

The release verifier therefore reports `NOT_REPRODUCED_MISSING_EXTERNAL_INPUTS` for EPA without searching unrelated folders, invoking the producer, making network requests, or modifying outputs. This is an honest scope boundary, not a successful native-data result.
