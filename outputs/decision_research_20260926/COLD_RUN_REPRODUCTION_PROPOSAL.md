# DRAFT ONLY: an input-driven cold reproduction of the fixed leader question

**Feasible in principle; HOLD implementation and execution until separate root
approval.** This proposes a reproducibility adapter, not new scientific scope,
a new estimator, or a replacement for the historical Stage3/Farkas records.
No code, freeze, field fit, LP, model enumeration, or new numerical result was
created for this assessment. Only this draft document was added.

## Benefit and limit

The present public release provides code, tests and aggregate results but cannot
replay omitted private proof objects. A genuinely input-driven command could
close a different gap: let another reviewer acquire the hash-pinned public EPA
archives, generate **new** certificates, and verify them independently without
obtaining any historical private ledger. That is material reproducibility value,
unlike merely rerunning known calculations for a new version number.

It would reproduce the same conditional mathematical question, not the exact
historical execution trace, floating solver choices, timestamps, proof multiplier
bytes or old ZIP hashes. The historical **34 non-unique / one HOLD** and separate
post-hoc completion remain untouched. The new procedure may return numerical
HOLDs on another runtime; it must neither assert predetermined outcomes nor
tune inputs or tolerances to recover the published totals.

## Scientific scope locked before implementation

- All 35 original Fresno/FINE receptor identities, in the original archive order;
  the same 20 species/selectors and original decimal means/uncertainties.
- The seven original family slots, including sources that a point fit might
  remove; no EVLS fitting or fitted-source pruning is needed.
- The same 120 distinct **actual historical profile tuples**, central first in
  the frozen Cartesian order. Each chosen record supplies its own mean **and**
  uncertainty fields, mapped to its original family label.
- Joint independent receptor/profile boxes at exactly k=2, nonnegative source
  contributions, no mass band, no composition constraint or profile envelope.
- The unchanged `delta = 1e-7 * max(1, TMAC)` with strict `bound > delta` for a
  positive margin certificate. No new k, threshold search, data, tracer or
  source-universe experiment.

The user-selectable scientific parameters should therefore be **none**. Input
directory, new output directory and explicitly declared resource ceilings are
operational settings, not permission to vary scientific assumptions.

## Why the existing command cannot simply be relabelled

Read-only source inspection found three historical dependencies:

1. `audit_interval_decisions.metadata_audit()` reads the old joint-profile
   ledger for the retained-source bridge, even though the proposed full-seven
   question does not need that bridge.
2. `verify_interval_certificate_records.load_original_inputs()` likewise reads
   that private ledger after its independent original archive parsing.
3. `audit_interval_profile_union.inputs_and_candidates()` requires the saved
   Stage2 index/cases, prior independent verification and exact historical
   31/2/2 partition. Its runner also contains a historical absolute cutoff.

Do **not** modify these frozen functions, fabricate a stand-in ledger, reset old
configuration hashes or treat historical public counts as candidate-selection
rules. New adapters can bypass the historical entry points while reusing
reviewed pure numerical/exact arithmetic functions.

## Minimum proposed workflow

1. **Preflight and new manifest.** Require an absent, explicit new private output
   directory. Verify all four archive hashes and their 39 recorded members,
   selector files, 35 distinct receptor identities, descriptor-based alternative
   mapping, all participating FINE profile records and nonnegative valid profile
   fields. Pin the existing core, grid, source-recovery metadata and new adapter
   code/test identities. Record runtime and new budgets before any LP. Check
   output containment, short filenames and writable paths before numerical work.
   Read ZIP members in memory; do not extract archive-controlled paths.

2. **Reconstruct the 35 central components anew.** Use the fixed full-seven
   central tuple and run only leader-relevant exact-core procedures. These are
   interval compatibility problems, not 35 new point fits. Save exact base
   feasibility/infeasibility, joint co-leader witnesses/exclusions and any
   leader-margin proof records. No source ranges, all-pair ranges, k=1/3 panels
   or 840-record audit is needed.

3. **Target remaining union questions from the new proofs.** For each sample
   without two already verified distinct co-leaders, visit the remaining actual
   tuples in the frozen order. Stop that sample as soon as two distinct family
   co-leaders have exact witnesses, possibly from different tuples. Retain all
   attempted, unresolved and unvisited statuses. Central infeasibility does
   not imply union infeasibility; a central unique leader does not certify the
   union. The historical set of four targeted samples is not an input.

4. **Prospectively specified two-route margin proof.** Reuse the frozen core's
   feasibility/co-leader and candidate-leader objective machinery. Where its
   six exact objective lower bounds do not establish the unchanged margin,
   apply the already reviewed Farkas algebra to the **newly saved** co-leader
   exclusions, without searching for different multipliers. This fallback
   requires an exact nonempty base, the same uniquely possible W, every other
   joint co-leader excluded, nonnegative augmented residual, gamma>0 and B>0,
   and all six `gamma/B > delta`. Equality remains HOLD. Keep both the original
   objective statuses and fallback derivation; do not make failed dual bounds
   disappear. No arbitrary source cap is permitted.

5. **Union conclusion.** Two exact distinct co-leader witnesses suffice for
   non-uniqueness and justify early stopping. A positive fixed-margin certificate
   requires all 120 distinct components accounted for, at least one nonempty
   component, exact infeasibility for the rest, and the same W with verified
   above-delta margins in every nonempty component. All 120 infeasible components
   mean an empty union, **not** a leader certificate. Missing models, unresolved
   premises, inadequate bounds or resource exhaustion remain separately labelled
   HOLDs. Account for every one of the 35 samples even if a global limit stops
   the run before a sample is visited.

6. **Independent no-LP replay.** Reconstruct the raw-input matrices separately
   from the archives and recheck every stored rational proof, row mapping,
   sample/tuple identity, source upper-bound provenance, strict threshold and
   conclusion. Freeze the new output manifest before replay. A successful
   numerical runner alone cannot promote the result. Comparison with historical
   aggregate findings is subsequent reporting, not an acceptance oracle.

## Reuse versus independence

The generating adapter may reuse `native.archive_inventory`,
`native.verify_recovery_identities`, `native.load_inputs`, the frozen
`core.field_model`, feasibility/co-leader/objective functions, and the pure
leader-inspection/Farkas routines. Do not call `native.run`, the historical
metadata/Stage2/Stage3 runners, or existing freeze modes. These public functions
already separate archive parsing from the optional point-fit experiment.

The independent adapter must **not** trust stored G/h/L/U or import the generating
adapter's tuple builder. It may reuse the independent exact verifier's table
parser, `reconstruct_model`, primitive proof checks and independent
`derive_component` Farkas derivation through a new public-only input reader.
Its reader must implement archive/member/selector/alternative identity checks
without the old bridge-ledger read. Merely calling the producer twice is not
independent verification. All frozen source files retain their current hashes.

The full independent chain must work in a clean checkout that has **no old
private directory** and only the declared public prerequisite commit/files plus
the four newly acquired archives. New private output is the only private input
to replay. The old 492/840 records and old targeted-sample metadata must be absent,
not silently discovered from a neighboring working directory.

## Budgets, safety and honest execution labels

At most 35 x 120 = 4,200 distinct sample/tuple models exist in scope; the central
models count within that ceiling. Ambiguity early stopping should avoid most of
them, but no historical runtime or number of targets is guaranteed.

A candidate operational ceiling is 20,000 LP calls and two elapsed hours, with
the 4,200-model scientific ceiling. These values require approval before a run;
they are **not** enough to promise complete worst-case enumeration. Count every
solver invocation, including feasibility helpers, cross-checks and failed
attempts, before making the call. Use a monotonic elapsed-time limit rather
than an embedded calendar date, and propagate remaining time to the solver.
Rational arithmetic and replay also need explicit time limits. Never extend a
budget automatically to obtain the expected result.

Use exclusive writes, short model-hash filenames and no overwrite/resume mode
in the minimal first implementation. Retain an interrupted run and its charged
budget as incomplete; a new separately authorized run gets a new identity.
No automatic upload, public proof-vector release or historical report rewrite.
An output is private because it contains raw-derived matrices and sample-level
records, even when its source archives are publicly downloadable.

A future command pair might be named `reproduce_interval_union.py` and
`verify_cold_interval_union.py`, with explicit input/output arguments. **Those
commands do not exist as part of this proposal.** A new guide must distinguish
fresh generation, independent replay of that generation, and historical replay.

## Required gates before any field run

- Approved fixed scientific manifest, byte-hash checks, complete acquisition
  instructions and public-base dependency closure; no private historical input.
- Independent producer/verifier model agreement on synthetic data and metadata-
  only reconstruction, including exact decimals, 35 ordered identities, all
  120 tuple mappings and each alternative's own uncertainty. Such a preflight
  must not fit or solve field models.
- Existing exact-core/Farkas adversarial tests plus new workflow tests: duplicate
  or omitted tuple/sample; wrong family/mean/uncertainty mapping; changed selector
  or archive; no nonempty component; two leaders in one or separate components;
  missing exclusion; same-W failure; negative residual/sign; zero B; equality
  with delta; unresolved dual with valid fallback; insufficient fallback; invalid
  proof; numerical failure; and early-stop proof completeness.
- Instrumented tests that fail on any attempted historical-ledger read, point
  fit, old output write or unbudgeted solver call. Budget exceptions must not be
  swallowed by numerical-error handling. Test interrupted writes, existing
  outputs, path length/containment and counter accounting.
- A clean input-free synthetic gate that explicitly skips native integration
  tests instead of accidentally refitting the 3,900-choice point grid.
- Independent review of new adapters **before** generating field records, then
  separate replay of every newly saved proof before any positive interpretation.

## Decision

**Worth proposing as a reproducibility improvement, not as more scientific
evidence.** It would let an outside reviewer regenerate verifiable conditional
answers without privileged access to historical proof ledgers. The minimum
implementation is nevertheless more than a command alias: new provenance
adapters, safe independent replay and clean-room tests are necessary.

Do not implement or run it merely to change the public release's label. Obtain
approval for this fixed scope and resource budget first. If prerequisites or
time for independent verification are unavailable, keep the current honest
public-subset limitation; do not ship an unreviewed cold-run promise or recreate
the entire historical multi-panel audit just to match old artifact hashes.
